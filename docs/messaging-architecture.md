# 消息架构与验收

## 数据路径

Flutter 页面通过 MessageRepository 调用一个受应用进程控制的 MethodChannel。Kotlin MainActivity 负责协议分派、角色申请和系统选择器；SmsRepository 访问 Telephony Provider；SmsTransport 负责提交发送与回执聚合。MessageStore 只管理本地状态，不复制整个系统短信库。

广播接收队列与界面查询队列分离，避免查询历史记录占用接收广播的执行机会。接收器使用 goAsync，完成后释放广播。消息变化通过 ContentObserver 合并后通知 Flutter。界面从系统库重新读取结果，不把发送请求被接受误报成已送达。

SMS 回执以消息 ID、分段索引和阶段去重。任何失败分段使对应阶段失败；所有分段成功后才显示最终状态。送达回执读取系统返回的 PDU 状态，暂态不当作已送达。

MMS 使用 Android SmsManager 执行运营商网络传输，第三方 PDU 库负责解析和持久化。临时传输文件放在应用私有目录，只通过非导出的、可授予单 URI 权限的 Provider 暴露。文件名只接受 UUID；附件按运营商上限有界读取，编码后的 PDU 再检查一次大小。

Rust 只接收待分析的正文列表，返回分类及可选验证码。FFI 代码由 flutter_rust_bridge 生成，不手工改写。解析规则不等同于诈骗判定，也不会宣称一条消息安全。

## 界面与动效

message_theme.dart 集中定义颜色、形状和路由过渡。列表、输入区域、消息气泡采用不同曲率；收发气泡保留方向性。动画随 Navigator 生命周期运行，页面离开后没有独立动画时钟。共享头像使用 Hero 衔接收件箱与会话。

系统减少动画设置会跳过自定义路由过渡。Material 控件仍遵循 Flutter 自身的组件行为。应用没有修改 Flutter Engine，因此不能把这一层描述成系统级渲染引擎。

## 真机验收

需要至少一台双卡 Android 设备和可用的运营商号码。安装测试包后，由设备使用者确认默认短信角色和权限。验收应包含：单条与多分段收发、SIM 切换、飞行模式、短信权限被撤销、进程退出后回执、重复回执、收件箱搜索、回收站恢复与删除，以及移动数据关闭后的 MMS 下载恢复。

大消息库的会话汇总仍需扫描 SMS Provider，当前没有额外维护全文索引。应以千条、万条消息分别测量首次加载和搜索耗时，再决定是否引入可失效重建的本地索引。不要用小数据集的流畅观感替代这个验证。

性能验收使用 profile 包记录启动、快速滚动、会话进入退出和键盘弹出时的帧耗时；报告设备、系统、刷新率、消息数量、温度条件及慢帧比例。尚未取得这些数据，因此没有任何渲染负载降低百分比。
